# Fabric RBAC

The `deployRbac` operation reconciles workspace roles and configured item-level direct access from `common.fabric.workspaces[].rbac`. Item assignments use Entra object IDs from `common.identities`; FWD translates group, user, and service-principal identities into the object-ID payload accepted by Fabric.

## SemanticModel and AppBackend direct access

The following item types have strict permission validation:

| Config `type` | Read endpoint | Write collection | `artifactPermissions` |
| --- | --- | --- | --- |
| `SemanticModel` | `/metadata/access/models/{modelIntId}?includeRestrictedUsers=true` | `models[]` in `PUT /metadata/access` | Omit or set to `0` |
| `AppBackend` | `/metadata/access/artifacts/{objectId}?includeRestrictedUsers=true` | `artifacts[]` in `PUT /metadata/access` | Omit or set to `0` |

SemanticModel access APIs require the internal integer model ID rather than the Fabric object ID. FWD resolves it through the workspace folder relation collection (`/metadata/relations/folder/{workspaceObjectId}`) by matching the SemanticModel object ID to a `Model` artifact. AppBackend is addressed directly by its Fabric object ID and uses the same artifacts access path as other supported Fabric items.

### SemanticModel permissions

Every configured non-zero SemanticModel value includes Read (`1`).

| Portal permissions | `detail[].permissions` |
| --- | ---: |
| Read | `1` |
| Read, Write | `3` |
| Read, Reshare | `5` |
| Read, Write, Reshare | `7` |
| Read, Build | `9` |
| Read, Write, Build | `11` |
| Read, Reshare, Build | `13` |
| Read, Write, Reshare, Build | `15` |

No other value is accepted. In particular, Build (`8`) without Read and unsupported bits such as `16`, `32`, `64`, or `128` fail configuration validation before any API request is made.

### AppBackend permissions

AppBackend values are limited to the combinations the Fabric portal can produce. Read (`1`) and Execute (`64`) are always present.

| Portal permissions | `detail[].permissions` |
| --- | ---: |
| Read, Execute | `65` |
| Read, Write, Execute | `67` |
| Read, Reshare, Execute | `69` |
| Read, Write, Reshare, Execute | `71` |

Values accepted by the API but not reachable through the portal, such as `1`, `3`, or `73`, are intentionally rejected. Removal is generated by reconciliation with permissions `0`; `0` is not a valid configured desired permission.

## Configuration example

```json
{
  "common": {
    "identities": [
      {
        "givenName": "Report Authors",
        "objectId": "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa",
        "principalType": "Group"
      }
    ],
    "fabric": {
      "workspaces": [
        {
          "name": "Analytics",
          "rbac": {
            "purgeUnmatchedRoleAssignments": true,
            "universalSecurity": {
              "sqlEndpoint": {
                "enabled": false
              }
            },
            "workspace": [],
            "items": [
              {
                "type": "SemanticModel",
                "displayName": "sales",
                "detail": [
                  {
                    "permissions": 9,
                    "objectId": "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa",
                    "purpose": "Read and Build for report authors"
                  }
                ]
              },
              {
                "type": "AppBackend",
                "displayName": "sales-insights",
                "detail": [
                  {
                    "permissions": 65,
                    "artifactPermissions": 0,
                    "objectId": "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa",
                    "purpose": "Run the Rayfin application"
                  }
                ]
              }
            ]
          }
        }
      ]
    }
  }
}
```

`artifactPermissions` is optional for both types. When present, it must be `0`.

## Authoritative purge safety

When `purgeUnmatchedRoleAssignments` is `true`, FWD removes unmatched direct item grants but preserves access derived from a workspace role:

- AppBackend responses identify inherited rows with a non-null `accessSource`; unmatched rows with that marker are skipped.
- SemanticModel responses do not expose `accessSource`. FWD therefore compares model rows with the object IDs returned by workspace RBAC and skips unmatched principals that currently hold a workspace role.
- A principal explicitly listed in the desired item `detail` is always reconciled to the configured value, even when the current row is workspace-role-derived.
- When `purgeUnmatchedRoleAssignments` is `false`, unmatched item rows are not removed.

AppBackend removal targets only the AppBackend object. FWD does not fan removal out to Rayfin-managed SQLDatabase or SQLEndpoint children; configure those items separately when they need direct access.

If a configured item is not present in the workspace, FWD logs a warning and continues. Existing matching assignments are idempotent and produce no write.
